# Kwak Yunsuk · 곽윤석

## LEVEL 4 - Advanced

컴퓨터 비전과 딥러닝을 연구하고, 소프트웨어를 만듭니다.

[LEVEL 1 - Beginner](%EB%A0%88%EB%B2%A81.md) · [LEVEL 2 - Explorer](%EB%A0%88%EB%B2%A82.md) · [LEVEL 3 - Practitioner](%EB%A0%88%EB%B2%A83.md) · **LEVEL 4 - Advanced** · [LEVEL 5 - Expert](%EB%A0%88%EB%B2%A85.md)

**구현을 이해하고 확장하는 분께** — **모듈 경계·설계 선택·실패 처리·실험 조건**을 살펴봅니다. 변경하려는 부분이 다른 단계와 결과 해석에 주는 영향을 함께 확인합니다.

**Python · C# · Arduino · Unity**를 사용합니다. Python은 실험·데이터 처리와 PC 기록에, C#은 Windows 프로그램과 Unity 게임 구현에 사용합니다. Arduino는 센서를 읽는 장치이고 Unity는 게임의 장면과 동작을 구성하는 개발 도구입니다. 아래 프로젝트의 기본 기능을 바탕으로 각 수준의 상세 안내로 이어집니다.

같은 프로젝트·차수·원문을 다루며, 레벨은 **설명의 출발점과 깊이**를 뜻합니다. 레벨을 높여야만 자료를 볼 수 있는 구조가 아닙니다. 프로젝트 이름을 누르면 **현재 레벨의 상세 안내**로 이동합니다.

플레이어 행동에 따라 **게임 상태·보상·화면이 바뀌는 흐름**을 구현합니다. 장면·상태 전이·시간·저장과 UI 동작의 일치를 확인합니다.

### [**Hole It Project**](https://github.com/PUVKID/Hole-It-Game-Project/blob/main/docs/%EC%9D%BD%EA%B8%B0%EC%95%88%EB%82%B4/%EB%A0%88%EB%B2%A84.md)

**접근 방법:** Unity 게임플레이

**이 레벨에서 읽을 내용:** **물체를 흡수하며 성장하는 게임.** GameManager 상태 전이·수집과 종료 조건·보상 처리·일시정지·로컬 저장 경계를 추적합니다. 장면과 UI 상태가 함께 바뀌는 지점을 확인합니다.


## 차수와 자료를 읽는 순서

1. **프로젝트의 목적과 입력·출력**을 먼저 읽습니다. 무엇을 받는지, 어떤 처리를 하는지, 무엇을 남기는지를 연결합니다.
2. **같은 레벨의 차수별 문서**로 이동합니다. 1차·2차는 개발·실험의 이력이고 LEVEL 1·2는 읽는 수준이므로 서로 다른 구분입니다.
3. **폴더·전체 비교·코드·논문**을 필요에 따라 열어 설명의 근거를 확인합니다. 같은 연구의 이전 원고를 별도 논문 실적으로 더하지 않습니다.
4. **관측 결과와 한계**를 함께 읽습니다. 계획·구현·실행·측정·게재는 각각 다른 상태이며, 하나를 다른 것의 증거로 대신하지 않습니다.

**숫자를 읽을 때:** 정확도·시간·표본 수는 조건과 단위를 같이 확인합니다. 원고에 실린 수치와 후속 실험의 결과를 합치지 않으며, 요약 표시와 저장 원값을 구분합니다.
